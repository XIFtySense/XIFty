# Plan #137: Tier S — PNG `tEXt`/`iTXt`/`zTXt` AI-prompt namespace (`xifty-meta-ai-gen`)

## Problem
Local AI tools (Automatic1111/Forge, ComfyUI/SwarmUI, InvokeAI, Fooocus, Midjourney) embed prompt/seed/model/sampler metadata in PNG text chunks, but XIFty currently surfaces those chunks only for IPTC and `Raw profile type *` framing. Probing of cloud-AI fixtures (#121) confirmed prompts never land in cloud images — so the embedded-decoder path is the *only* honest source for this metadata. We need a normalized `ai_gen.*` namespace populated from `tEXt`/`iTXt`/`zTXt` keys (`parameters`, `prompt`, `workflow`, `invokeai_metadata`, `Description`, `Comment`).

## Approach
Mirror the post-#140 architecture: PNG container exposes raw chunk bytes via `text_payloads()` + `decode_text_chunk` (already public — `crates/xifty-container-png/src/lib.rs:39-45` and `:201-243`); the new meta crate `xifty-meta-ai-gen` consumes `(keyword, body)` and returns `Vec<MetadataEntry>` plus `Vec<Issue>` in the `ai_gen` namespace; CLI dispatch lives in the existing PNG text-chunk loop in `crates/xifty-cli/src/lib.rs:424-568`, slotted *before* the `Raw profile type *` classifier so AI keywords (`parameters`, `prompt`, `workflow`, `invokeai_metadata`, `Description`, `Comment`) take priority. Internal organization mirrors `xifty-meta-iptc` (`Cargo.toml` deps `xifty-core` + `serde_json`, `decode_payload(AiGenPayload)` entry point, per-shape sub-modules). `TypedValue` has no array/object variants so `lora`/`controlnet` arrays are flattened as `ai_gen.lora.<i>.name` / `ai_gen.lora.<i>.weight` (same pattern #131 used). Confidence is encoded as a note (`"ai_gen_confidence: 0.95"`) since `MetadataEntry` has no confidence field — normalization (`xifty-normalize`) can promote it later.

## New files
- `crates/xifty-meta-ai-gen/Cargo.toml` — package manifest. Deps: `xifty-core` (path) and workspace `serde_json` (for ComfyUI/InvokeAI/Fooocus JSON walks). **No** dep on any container crate.
- `crates/xifty-meta-ai-gen/src/lib.rs` — public surface: `pub struct AiGenPayload<'a> { keyword: &'a str, body: &'a [u8], container: &'a str, offset_start: u64, offset_end: u64 }`, `pub fn decode_payload(payload: AiGenPayload<'_>) -> (Vec<MetadataEntry>, Vec<Issue>)`, `pub fn classify_keyword(keyword: &str) -> Option<AiGenShape>` (`A1111Parameters | ComfyPrompt | ComfyWorkflow | InvokeAiMetadata | MidjourneyDescription | MidjourneyComment | FooocusParameters`), `pub fn supported_fields() -> &'static [&'static str]`. Entry point routes by shape and accumulates entries.
- `crates/xifty-meta-ai-gen/src/a1111.rs` — A1111/Forge plaintext parser. Splits body on first `\nNegative prompt:` (optional); the trailing line (last `\n`-delimited line that begins with a known A1111 token like `Steps:` or `Sampler:`) is tokenized respecting double-quoted segments. Recognised keys: `Steps`, `Sampler`, `Schedule type`/`Scheduler`, `CFG scale`, `Seed`, `Size` (`<W>x<H>` → `ai_gen.dimensions.{width,height}`), `Model hash`, `Model`, `Lora hashes` (`name: hash` pairs), explicit `<lora:NAME:WEIGHT>` tags inside the prompt body (extract with a small scanner). Unknown keys are preserved verbatim as `ai_gen.tool_extra.<key>` entries. Tool tag = `automatic1111`. Confidence 0.95 when at least one of `Steps:`/`Sampler:`/`Seed:` parsed; 0.7 when only the prompt body decoded.
- `crates/xifty-meta-ai-gen/src/comfyui.rs` — `serde_json::Value` walker. Parses `prompt` (API JSON: object map of node-id → `{class_type, inputs}`) and `workflow` (graph JSON with `nodes[]`). Pulls positive/negative prompts from `CLIPTextEncode` nodes (the convention is two such nodes; positive is whichever feeds the `KSampler.positive` link, otherwise the first; the second becomes negative — when ambiguous, emit both as `ai_gen.prompt` and `ai_gen.negative_prompt` with a `"comfy_prompt_role: heuristic"` note). `KSampler` provides `seed`, `steps`, `cfg`, `sampler_name`, `scheduler`. `CheckpointLoaderSimple.inputs.ckpt_name` → `ai_gen.model.name`. `LoraLoader` nodes → `ai_gen.lora.<i>.{name, weight}`. The full `workflow` JSON is preserved as `ai_gen.workflow_json` (`TypedValue::Bytes` carrying UTF-8 JSON — closest to a "blob" given current `TypedValue`; tagged with note `"format: json"`). Tool tag = `comfyui`. Confidence 0.95 if `KSampler` + at least one `CLIPTextEncode` found.
- `crates/xifty-meta-ai-gen/src/invokeai.rs` — `serde_json::Value` parse of `invokeai_metadata`. Direct field map: `positive_prompt`/`prompt` → `ai_gen.prompt`; `negative_prompt` → `ai_gen.negative_prompt`; `seed` → `ai_gen.seed`; `steps` → `ai_gen.steps`; `cfg_scale` → `ai_gen.cfg_scale`; `model.name`/`model.hash` → `ai_gen.model.{name,hash}`; `scheduler` → `ai_gen.scheduler`; `width`/`height` → `ai_gen.dimensions.*`; `loras[]` → `ai_gen.lora.<i>.{name,weight}`; `controlnets[]` → `ai_gen.controlnet.<i>.*`. Tool tag = `invokeai`. Confidence 0.95.
- `crates/xifty-meta-ai-gen/src/midjourney.rs` — Plaintext parser for `Description` / `Comment`. Prompt body = the full string with the trailing Job UUID stripped. Job UUID detected by matching a 36-char `[0-9a-fA-F-]{36}` token (8-4-4-4-12 dash pattern) at the tail or after the substring `Job ID:` / `--job_id`. Emits `ai_gen.prompt` and `ai_gen.midjourney.job_id` when found. Tool tag = `midjourney`. Confidence 0.7 (heuristic).
- `crates/xifty-meta-ai-gen/src/fooocus.rs` — JSON variant of `parameters`. Tries `serde_json::from_slice::<Value>(body)` first; if successful and the JSON has `prompt` + (`base_model`/`base_model_name`) keys, treat as Fooocus. Otherwise return `None` so the A1111 plaintext parser is the fallback (chained from `lib.rs` dispatch). Tool tag = `fooocus`. Confidence 0.95.
- `crates/xifty-meta-ai-gen/src/keys.rs` — Constants: `pub const NS: &str = "ai_gen";` and the bounded field-name list (also returned by `supported_fields()` so `CAPABILITIES.json` can be cross-checked).
- `tools/gen_ai_gen_fixtures.py` — Stdlib-only fixture generator (zlib + struct + binascii, mirroring `gen_raw_profile_fixtures.py:1-50`). Writes:
  - `fixtures/minimal/ai_gen_a1111.png` (`tEXt` keyword `parameters`, A1111 plaintext body)
  - `fixtures/minimal/ai_gen_comfyui.png` (`tEXt` keys `prompt` + `workflow`, minimal API + graph JSON)
  - `fixtures/minimal/ai_gen_invokeai.png` (`iTXt` keyword `invokeai_metadata`)
  - `fixtures/minimal/ai_gen_midjourney.png` (`iTXt` keyword `Description` with prompt + UUID)
  - `fixtures/minimal/ai_gen_fooocus.png` (`tEXt` keyword `parameters` with JSON body)
- `crates/xifty-meta-ai-gen/tests/decode.rs` — Integration tests; one per shape; each builds its body in-memory (no fixture coupling) and asserts the produced `MetadataEntry` set.
- `crates/xifty-cli/tests/snapshots/<name>.snap` — Five new insta snapshots, one per fixture, generated via `cargo insta review` during build. (Pattern follows existing PNG fixture snapshots; reviewer must `cargo insta review`, not blanket-accept.)

## Risks
- **A1111 grammar drift**: trailing-line tokenizer must respect quoted commas (`Sampler: "DPM++ 2M, Karras"`). Test with at least one quoted-value fixture.
- **ComfyUI prompt-role ambiguity**: `KSampler` has `positive` and `negative` input refs; following the link graph is the correct way to tell positive from negative. If link-resolution is too fragile, fall back to a heuristic (first `CLIPTextEncode` is positive, second is negative) and emit a note. Document the chosen strategy in the module docstring.
- **`TypedValue` lacks a blob/JSON variant**: `ai_gen.workflow_json` rides on `TypedValue::Bytes` with a `format: json` note. If a follow-up adds a typed JSON variant, this becomes a one-line migration. Schema_version stays at 0.1.0 (additive).
- **Keyword collision with `Raw profile type *`**: dispatcher ordering is load-bearing. Place AI-gen check **before** raw-profile classification to prevent any future `Raw profile type parameters` collision. Add a regression test that asserts a `parameters` keyword does not match `classify_raw_profile_keyword`.
- **Fooocus / A1111 ambiguity** on the same `parameters` keyword: try JSON parse first; only fall back to A1111 plaintext when JSON parse fails. Test both directions with identical keyword.
- **Midjourney heuristic confidence**: `Description` is a generic PNG keyword used by many tools. Restrict the Midjourney shape to bodies where a 36-char UUID is present *or* the body contains `--ar`/`--v`/`--style` Midjourney-specific flags; otherwise emit nothing and let other classifiers try.
- **Fixture realism**: synthetic fixtures cover decoder logic but not real-world quirks. Issue lists this as acceptable for v1; mark any `#[ignore]`'d real-fixture tests with the originating tool name + version.
