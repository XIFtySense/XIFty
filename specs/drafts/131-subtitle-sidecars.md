# Plan #131: Tier S — subtitle sidecars (.srt / .vtt / .ass) for video

## Problem
Subtitle sidecars (`<basename>.srt`, `<basename>.<lang>.srt`, `<basename>.vtt`, `<basename>.ass`/`.ssa`) are the most universal sidecar pattern in video — every YouTube uploader, video editor, and podcast-with-video creator ships them next to their `.mp4`/`.mov` files. XIFty silently ignores them today. Issue #131 asks for a new adapter that discovers all subtitle siblings, parses headers/cues, and surfaces a normalized field surface (format, language from filename, cue count, duration, first-cue preview, path) so consumers can answer "what languages does this video have captions in?" from the envelope alone. Phase 1 (#122) shipped the `Sidecar` trait + registry — this is the second concrete adapter and the first that uses non-XML, line-based parsing.

## Approach
Create `crates/xifty-sidecar-subtitles/` mirroring `crates/xifty-sidecar-sony-nrt/` exactly: a single `Sidecar`-impl struct, file-system discovery in the parent directory of the primary path, `MergePolicy::Complement`, native Rust parsers (no third-party deps — SRT/VTT/ASS are line-based, no `quick-xml` needed), and per-sidecar `MetadataEntry` records emitted into the `subtitles` namespace with `Provenance::container = "sidecar"` and `Provenance::path` pointing at each subtitle file. Discovery walks `parent_dir`, matches `<stem>.<ext>` and `<stem>.<lang>.<ext>` for `srt|vtt|ass|ssa` (case-insensitive), emits one `SidecarRef` per file. Parsing uses three small dedicated parsers (one per format) that extract: cue count, last-cue end timestamp (→ `duration_seconds`), first cue's first 200 chars, and (for ASS) style count from the `[V4+ Styles]` section. Language is derived from the filename pattern at discover-time (validated against a small BCP 47 / ISO 639 token shape; fallback `und`). Each discovered sidecar produces a flat group of entries keyed `subtitles.<i>.format`, `subtitles.<i>.language`, `subtitles.<i>.cue_count`, `subtitles.<i>.duration_seconds`, `subtitles.<i>.path`, `subtitles.<i>.first_cue_text` — index-prefixed in discovery order, mirroring how sony_nrt flattens nested XML attributes. Register the adapter in `xifty-cli::default_sidecar_registry()` so it ships behind the existing `--sidecars` opt-in flag.

## Step-by-step
1. **Workspace registration** — add `crates/xifty-sidecar-subtitles` to root `Cargo.toml` `[workspace] members`. Verify `cargo metadata` resolves it cleanly.
2. **Crate skeleton** — create `Cargo.toml` mirroring `crates/xifty-sidecar-sony-nrt/Cargo.toml` (drop `quick-xml`, keep `xifty-core` + `xifty-sidecar` path deps, inherit version/edition/license from workspace).
3. **Constants + struct** — declare `NAMESPACE = "subtitles"`, `CONTAINER = "sidecar"`, the `pub struct SubtitlesSidecar;` with `pub const fn new()`, and a small `Format` enum (`Srt`, `Vtt`, `Ass`).
4. **Discovery** — implement `fn discover_in_dir(primary: &Path) -> Vec<SidecarRef>` that: (a) returns empty if `primary.parent()` is None; (b) walks `read_dir` once; (c) for each entry whose extension (case-insensitive) is `srt|vtt|ass|ssa`, checks whether `entry.file_stem()` equals `primary.file_stem()` (bare match) OR equals `<primary_stem>.<lang_token>` where `lang_token` is 2–8 chars of `[A-Za-z0-9-]`; (d) emits `SidecarRef { path, label: format!("{format}/{lang}") }` per hit; (e) sorts results deterministically by `(format, language, path)` so test assertions are stable. Wire `Sidecar::discover` to call it; buffer-only callers (`primary_path == None`) get an empty Vec, matching sony_nrt's contract (lib.rs:49-54).
5. **SRT parser** — line-based scanner over UTF-8 (strip optional UTF-8 BOM): count cue blocks (a numeric line followed by a `--> ` timing line), capture the first cue's text (up to 200 chars after stripping HTML-ish `<i>`/`<b>` tags is *not* required — just raw chars), and parse the LAST `--> ` line's right-hand timestamp (`HH:MM:SS,mmm`) into `f64` seconds for `duration_seconds`. Robust to `\r\n` vs `\n`, blank trailing lines, missing cue numbers (some authoring tools omit them).
6. **VTT parser** — same shape as SRT but the file MUST start with `WEBVTT` (followed by optional space/tab + header text + newline). Time format uses `.` (period) not `,` for ms. Skip `NOTE` blocks, `STYLE` blocks, and cue identifiers. Reuse the SRT timestamp parser's logic by allowing both `,` and `.`.
7. **ASS / SSA parser** — section-aware line scanner. Track `[Script Info]`, `[V4+ Styles]` / `[V4 Styles]`, and `[Events]`. Count `Style:` lines under styles section → `style_count`. Count `Dialogue:` lines under events → `cue_count`. Parse the `Start` / `End` columns from the `Format:` line under `[Events]` (column ordering is not fixed; ASS lets authors reorder). Last `Dialogue:` row's `End` field → `duration_seconds` (ASS time format `H:MM:SS.cs`). First `Dialogue:` row's `Text` column (last column per format spec, may contain commas) → `first_cue_text`. Surface `subtitles.<i>.style_count` only for ASS entries.
8. **Filename language extraction** — `fn parse_language_from_stem(file_stem, primary_stem) -> Option<String>` that returns `Some("en")` for `movie.en` when `primary_stem == "movie"`, validates the token against a permissive BCP 47 regex equivalent (2–8 ASCII alphanumerics/dash, leading char alphabetic), returns `None` otherwise. Discovery emits `subtitles.<i>.language = "und"` via `TypedValue::String("und".into())` when `None` (per acceptance criteria: "emit `und` if not parseable").
9. **Entry emission** — per-sidecar `push_string` / `push_integer` / `push_float` helpers identical in shape to sony_nrt's (lib.rs:588-625), all stamping `provenance.container = "sidecar"`, `provenance.namespace = "subtitles"`, `provenance.path = Some(sidecar.path.to_string_lossy())`, `provenance.notes = vec![format!("subtitles sidecar ({})", sidecar.label)]`. Tag names follow `subtitles.<i>.<field>` with `i` matching the discovery-order index.
10. **Parse error surfacing** — on truly malformed input (e.g. `.srt` whose first non-blank cue has no `--> ` line at all), emit a single `Issue` with code `SIDECAR_PARSE_ERROR`, `Severity::Warning`, `context: Some("subtitles".into())` — exactly like sony_nrt's pattern at lib.rs:469-478 — but still emit whatever fields *did* parse (graceful degradation; matches Vision principle 7).
11. **Unit tests in `lib.rs`** — synthetic fixtures embedded as `const &str` for each format: `MIN_SRT`, `MIN_VTT`, `MIN_ASS`. Tests:
    - parses each format end-to-end and surfaces all six (or seven for ASS) tag suffixes;
    - language extraction: `movie.en.srt` → `en`; `movie.srt` → `und`; `movie.bogusname.srt` → `und` only if `bogusname` fails the BCP 47 token shape (else accepted);
    - discovery returns empty for `primary_path == None`;
    - discovery finds multiple co-located sidecars in one directory and emits stable order;
    - malformed SRT (no timing lines) emits `SIDECAR_PARSE_ERROR` warning but does not panic;
    - VTT without `WEBVTT` header produces `SIDECAR_PARSE_ERROR` and falls through;
    - last-cue timestamp parses to expected `f64` seconds;
    - first_cue_text truncates at 200 chars.
12. **CLI registration** — edit `crates/xifty-cli/src/lib.rs` to add `use xifty_sidecar_subtitles::SubtitlesSidecar;` near the existing sony_nrt import (line 52) and `registry.register(SubtitlesSidecar::new());` inside `default_sidecar_registry()` (line 234-235 region). Existing `enable_sidecars` flag flow is unchanged.
13. **Integration test (real fixture)** — append a `subtitles_sidecar_*` test to `crates/xifty-cli/tests/cli_contract.rs` after the sony_nrt block (~line 3168). ## Risks
- **Field-shape ambiguity in the issue body vs. user prompt.** Issue #131 specifies `subtitles[]` as an array of objects (`subtitles[].format`, `.language`, …). The `Sidecar` trait emits a flat `Vec<MetadataEntry>` keyed by `tag_name`, so we serialize the array as index-prefixed flat tags `subtitles.<i>.<field>` (matching how sony_nrt flattens `Device.serialNo`). A nested-array projection would have to live in `xifty-normalize` (out of scope here — sony_nrt didn't get one for Phase 1 either). Plan-reviewer should confirm this flat shape is acceptable; if not, the alternative is a `TypedValue::Array` change which reaches into `xifty-core` and is much larger surface area.
- **Filename language extraction is heuristic.** `movie.final.srt` and `movie.fixed.srt` both look like language tags by the regex shape — they'll surface as `language = "final"` / `"fixed"`. Mitigation: validate against a small BCP 47 token whitelist (2–3 letter ISO 639 + optional region subtag) before accepting; emit `und` for everything else. Document in code comments and accept this is a best-effort heuristic — the issue accepts `und` as the fallback.
- **ASS cue/timing complexity.** The `[Events]` `Format:` line lets authors reorder fields, and the `Text` field is comma-bearing. Plan calls out using the `Format:` header column index lookup rather than positional split. Real-world ASS files are mostly anime fan-subs with stable column order, but synthetic fixtures should exercise reordered headers to keep the parser honest.
- **Discovery scope for very dense directories.** `read_dir` once per `discover()` call is cheap, but a directory with 1000+ files would scan all of them. This matches sony_nrt's approach at `crates/xifty-sidecar-sony-nrt/src/lib.rs:82-110`; no new risk introduced.
- **Graphical/binary subtitle formats** (`.idx`/`.sub`, PGS) are explicitly out of scope per the issue body — confirm the plan does not bleed into them.
- **Embedded subtitle tracks** (MP4/MKV `tx3g`, MOV captions) are explicitly deferred to a possible `xifty-meta-subtitle-track` follow-up — this plan stays sidecar-only.
